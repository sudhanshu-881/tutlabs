# Production Deployment Guide (Vercel & Supabase)

This guide will walk you through setting up your Supabase backend and deploying the tutlabs application to Vercel.

## Part 1: Supabase Setup

### 1. Create a Supabase Project
- Go to [supabase.com](https://supabase.com), sign in, and click **"New project"**.
- Give your project a name and a strong database password.
- Save your **Project URL** and **`anon` public key**. You will find these in your project's dashboard under `Settings > API`. You will need them for Part 2.

### 2. Set up Database Tables & RLS
- Navigate to the **SQL Editor** in your Supabase project dashboard (the icon looks like a page with `SQL` on it).
- Click **"+ New query"**.
- Copy the entire SQL script below and paste it into the editor.
- Click **"Run"**. This script will:
    1. Create the `profiles`, `tutors`, and `students` tables required by the application.
    2. Create a database function and trigger to automatically create a user profile upon signup.
    3. Enable Row Level Security (RLS) to protect your data.
    4. Add the specific security policies mentioned in the source code to control who can access and modify data.
    5. Insert some sample data so the app looks populated on its first load.

#### **Supabase SQL Script**
```sql
-- 1. PROFILES TABLE
-- Stores public user data, linked to the authentication system.
create table public.profiles (
  id uuid not null references auth.users on delete cascade,
  updated_at timestamp with time zone,
  full_name text,
  avatar_url text,
  education text,
  experience text,
  location text,
  active_role text not null default 'student'::text,

  primary key (id),
  constraint full_name_length check (char_length(full_name) >= 3)
);
comment on table public.profiles is 'Public profile information for each user.';
alter table public.profiles enable row level security;


-- 2. TUTORS TABLE
-- Stores data for tutor listings.
create table public.tutors (
    id bigint generated by default as identity,
    name text not null,
    subjects text[] not null,
    location text,
    rating numeric not null,
    image_url text,
    verified boolean default false,
    created_at timestamp with time zone not null default now(),

    primary key (id)
);
alter table public.tutors enable row level security;


-- 3. STUDENTS TABLE
-- Stores data for student listings.
create table public.students (
    id bigint generated by default as identity,
    name text not null,
    learning_goals text[] not null,
    location text,
    level text,
    image_url text,
    created_at timestamp with time zone not null default now(),

    primary key (id)
);
alter table public.students enable row level security;


-- 4. FUNCTION TO CREATE A PROFILE ON SIGNUP
-- This function is triggered when a new user signs up.
create or replace function public.handle_new_user()
returns trigger
language plpgsql
security definer set search_path = public
as $$
begin
  insert into public.profiles (id, full_name, active_role)
  values (new.id, new.raw_user_meta_data->>'full_name', 'student');
  return new;
end;
$$;


-- 5. TRIGGER FOR THE FUNCTION
-- This trigger calls the function when a new user is added to auth.users.
create trigger on_auth_user_created
  after insert on auth.users
  for each row execute procedure public.handle_new_user();


-- 6. RLS POLICIES (CRITICAL FOR SECURITY)
-- Profiles Table Policies
create policy "Public profiles are viewable by everyone."
  on public.profiles for select
  using ( true );

create policy "Users can insert their own profile."
  on public.profiles for insert
  with check ( auth.uid() = id );

create policy "Users can update their own profile."
  on public.profiles for update
  using ( auth.uid() = id );

-- Tutors Table Policies
create policy "Tutors are publicly visible."
  on public.tutors for select
  using (true);

-- Students Table Policies
create policy "Students are publicly visible."
  on public.students for select
  using (true);
```

### 3. Set up Storage for Avatars
- In your Supabase dashboard, go to **Storage** (the bucket icon).
- Click **"New bucket"**.
- Name the bucket `avatars` and click **"Create bucket"**.
- After creating it, go to its policies by clicking the three dots (`...`) next to the bucket name and selecting **"Policies"**.
- Click **"New policy"** and create the following policies to secure your bucket:
    - **Policy 1: Allow anyone to view avatars.** (This makes images public)
        - Select the template: `Give users read access to objects`
        - For `Allowed operations`, check `SELECT`.
        - Give it a descriptive name like `Public read access for avatars` and save.
    - **Policy 2: Allow authenticated users to upload their own avatar.**
        - Select the template: `Allow authenticated users to upload`
        - For `Allowed operations`, check `INSERT`.
        - For the policy definition, add this `WITH CHECK` expression: `bucket_id = 'avatars' AND (storage.foldername(name))[1] = auth.uid()::text`
        - Give it a name like `Allow users to upload own avatar` and save.
    - **Policy 3: Allow users to update/delete their own avatar.**
        - Create another new policy from scratch.
        - For `Allowed operations`, check `UPDATE` and `DELETE`.
        - For `Target roles`, check `authenticated`.
        - For the policy definition (`USING` expression), use: `bucket_id = 'avatars' AND auth.uid() = (storage.foldername(name))[1]::uuid`
        - Give it a name like `Allow users to manage their own avatar` and save.


## Part 2: Vercel Deployment

### 1. Push Your Code to GitHub
- Make sure your latest code, including the changes from this session, is pushed to a GitHub repository.

### 2. Create a Vercel Project
- Go to [vercel.com](https://vercel.com) and sign up/log in with your GitHub account.
- On your dashboard, click **"Add New... -> Project"**.
- **Import** the GitHub repository for this project.
- Vercel should automatically detect it as a **Vite** project. The build settings can be left as default.

### 3. Configure Environment Variables
- In the project configuration screen, expand the **Environment Variables** section.
- Add the following two variables, using the credentials you saved from your Supabase project in Part 1.
    - **Name:** `VITE_SUPABASE_URL`, **Value:** Your Supabase project URL (e.g., `https://xyz.supabase.co`)
    - **Name:** `VITE_SUPABASE_ANON_KEY`, **Value:** Your Supabase `anon` public key.
- Click **"Deploy"**.

## Part 3: Final Supabase Configuration

Once Vercel has finished deploying, it will give you a production URL (e.g., `https://your-project-name.vercel.app`).

- Go back to your Supabase project dashboard.
- Navigate to **Authentication > URL Configuration**.
- In the **Site URL** field, enter your Vercel deployment URL.
- Under **Redirect URLs**, add your Vercel URL as well.
- Click **Save**.

Your application is now fully configured and live!
